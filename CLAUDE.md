# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Flask web app (UI in Indonesian) presenting SVR (RBF kernel) rice-price predictions for Kabupaten Langkat, with weather (Temperatur, Curah Hujan) as exogenous features. 6 rice categories, daily data 2020-2024. See `README.md` for dataset/feature/metric details.

## Commands

```bash
pip3 install -r requirements.txt   # app deps only (Flask, numpy, pandas, pymysql, Werkzeug)
python3 app.py                     # runs on http://localhost:5000 (debug=True)
```

- Must be run from the repo root: `app.py` resolves `flask_components/` and `static/` via `os.getcwd()`.
- Admin login: `admin` / `admin123` (hardcoded in `app.py`).
- No tests or linter are configured.
- `python update_data.py cuaca` appends new daily weather (Open-Meteo, Stabat coordinates) to `cuaca_harian.xlsx` and writes a `.backup.xlsx` first. `python update_data.py harga-inspect` only dumps a raw PIHPS price response to `pihps_raw.json`; there is no price parser yet.
- Retraining: run all cells of `train.ipynb` in order, from the repo root (it writes to relative `flask_components/...` paths). Headless: `python -m nbconvert --to notebook --execute --inplace train.ipynb` (the `jupyter` shell command may not be on PATH). It needs scikit-learn and Plotly, which are NOT in `requirements.txt`. Afterwards re-run `python export_model_details.py`.

## Architecture

**The app does not run the model.** Training happens offline in `train.ipynb`, which writes everything into `flask_components/`. `app.py` is a read-only presentation layer over those artifacts. The `.pkl` files in `flask_components/models/` are never loaded by the app. Changing a metric, prediction or chart means re-running the notebook, not editing Flask code.

**Model target:** each SVR predicts the price *difference* from `lag1` (`y - lag1`), then adds `lag1` back. Predicting absolute price made RBF-SVR under-predict systematically (it cannot extrapolate beyond the training price range; MAPE 5.66%). The delta target gives avg MAPE about 0.49%. The same `+ lag1` step must be applied wherever a model is called (notebook cells 6, 12, 16). The 1095-day recursive forecast (cell 16) multiplies the predicted delta by `DAMPING_PHI ** day` (0.98); without damping, a small daily bias compounds and prices diverge (Super I reached Rp28,000). The naive lag-1 baseline still beats SVR on 1-day MAPE (about 0.12-0.24%), so keep reporting both.

Artifacts consumed by routes in `app.py`:
- `flask_components/results/svr_results.json` — per-category `testing_metrics` (mape/mae/rmse). Averages, best and worst category are computed from it in every route.
- `flask_components/data/dataset_info.json` — `kategori_beras` (the category list that drives everything), `periode`, `descriptive_statistics`, `weather_statistics`, `weather_price_correlation`.
- `flask_components/data/splitting_info.json`, `preprocessing_info.json` — record counts and feature lists.
- `flask_components/results/final_performance_summary.json` — SVR hyperparameters (C, epsilon, gamma), read by `load_model_parameters()` for `/tentang` and `/analisis`.
- `flask_components/data/model_details.json` (gamma value, support-vector count per category) and `data/merek_beras.json` (brands per category) — injected into ALL templates by the `inject_merek_beras` context processor. `model_details.json` is generated by `python export_model_details.py`, which is the one script that does unpickle `svr_models.pkl`. Re-run it after retraining.
- `flask_components/results/display_predictions_<Kategori_with_underscores>.csv` — `/analisis` detail tables (formatted strings like `Rp 12,000` and `5.1%` that the route parses back to floats).
- `flask_components/data/future_predictions_<Kategori>.csv` and `results/future_predictions_summary.json`, `historical_vs_future_comparison.csv` — `/prediksi`, which just takes `.head(N)` of the precomputed forecast (1095 days, 2025-01-01 to 2027-12-31).
- `flask_components/visualizations/*.html` — Plotly charts. Routes copy them into `static/visualizations/` (only if newer) and pass a `key -> filename` dict to templates, which embed them. `static/visualizations/` is generated, so edit the source in `flask_components/visualizations/`.

Routes: public `/`; `@login_required` (session-based) `/dashboard`, `/analisis`, `/prediksi` (GET/POST), `/tentang`; `/admin/login`, `/logout`; `/api/*` are stubs. Templates are under `templates/<page>/index.html` extending `layouts/main_layout.html`.

## Gotchas

- Each route repeats the same load-JSON, compute-averages and MAPE-interpretation logic, with hardcoded fallback defaults (1228 records, MAPE 0.49, and so on; keep them in sync with the latest `svr_results.json`). If you change the logic, update all routes (`homepage`, `dashboard`, `tentang`, `analisis`).
- The record-count key differs between routes: `splitting_info.json` has `total_records`, which only `/analisis` reads. `homepage`, `dashboard` and `tentang` look for `total_samples` (absent), so they fall back to other sources or hardcoded defaults.
- `flask_components/results/baseline_comparison.csv` (SVR vs naive lag-1) is shown on the `/analisis` performance tab.
- The `1095` forecast-day default in `/prediksi` is duplicated in `app.py` and must match `future_predictions_summary.json`.
- Category-to-filename convention: `kategori.replace(' ', '_')`. Keep this when adding artifacts.
- `templates/dashboard/Index.html` is capitalized but rendered as `dashboard/index.html`. It works on Windows and will break on case-sensitive filesystems.
- `pymysql`, `pickle`, `csv`, `secure_filename`, `io`, `send_file` are imported but unused.
